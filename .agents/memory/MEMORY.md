- **A test can delete production tables (2026-09-18):** `signalAccuracyDigest.test.ts`'s `DROP TABLE IF EXISTS` removed `high_flyer_daily_stats`/`high_flyer_retrospective` from live for 21 days; found by `schema:drift`, not by any suite. Guarded by `src/server/__tests__/testsDoNotDropProductionTables.test.ts` (source-derived scan — a test issuing DROP must assert `VITEST_PG_SCHEMA`). Tell: a subsystem loses exactly the objects some test NAMES and keeps the ones it doesn't.
- **`db_compat.safe_alter(conn, ddl)` now USES the conn you pass it (2026-09-18).** It previously documented the argument as "accepted and ignored" and opened its own connection, so ALTERs against a table created in the caller's open transaction failed silently. Pass `None` only for an already-committed table.
- **Provider-id reverse maps go through `src/server/mc_symbol_map.py`** (2026-09-18): 62 of 2,340 `mcsymbol` codes map to >1 NSE symbol (`KMF → {KOTAK, KOTAKBANK, MAHINDRA}`), so `{row["mcsymbol"]: row["symbol"] for ...}` silently misattributes. Build `code → set(symbols)`, keep singletons, drop and report the rest.
- **ROE lives in `investsights_fundamentals_history.return_on_equity`** (2026-09-18), NOT in `investsights_factor_scores.roe` (a different definition: Pearson 0.7727 vs yfinance, percent scale, sign flips). The good one measures Pearson 0.9608, same fraction scale, zero sign flips. Yahoo's own `stock_fundamentals.return_on_equity` decayed 86% → 6.1% over six weeks; watched by `fundamentals-history-vendor-field-decay` in `dataQualityChecks.ts`.
- **Block-deal HISTORY comes from MoneyControl, not NSE** (2026-09-18): `mc_block_deal_history_fetcher.py` (`mc-block-data?scId=<mcsymbol>&page=N`, auth NONE, UA+Referer only, paginate on `seemore`). NSE's historical ranges are 503; only `/api/block-deal` (today) works. Weekly inside `ml-weekly-data`.
- **`bharat_alpha`'s test Postgres is NOT running in a fresh cloud container** (2026-09-29): the suite needs a cluster on **port 55432** with trust auth. Start it with `sudo -u postgres /usr/lib/postgresql/16/bin/pg_ctl -D /var/lib/postgresql/16/main -o "-p 55432 -k /tmp -c config_file=/etc/postgresql/16/main/postgresql.conf -c hba_file=/tmp/pg_hba_trust.conf" -l /tmp/pg55432.log start` (the trust hba is 3 lines: `local all all trust` + the two 127.0.0.1/::1 host lines). Without it every DB test ERRORS at setup, which looks like a code break and is not. A container restart mid-session loses it.
- **CI and the dev container run DIFFERENT major pandas versions** (2026-09-29): CI resolves 3.x, containers here had 2.3.3, `pyproject` says `>=2.2`. Two CI-only failures in one session came from it — a NULL text column reading as `nan` vs `None`, and `Series.to_numpy()` being READ-ONLY on 3. Guarded by `bharat_alpha/tests/test_no_numpy_view_writes.py`; full class in `.claude/rules/bugs-testing-env.md`.

NSE revises lots, so a contract-count change over time is not an exposure change. `alpha.fo_daily.lot_size`, migration 0009.
