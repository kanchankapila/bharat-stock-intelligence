Design — Section 2 of 3: Services

Four new components. Each has one job. Does this decomposition look right?

1. screener_classifier.ts
src/server/screenerClassifier.ts — TypeScript
One-time + on new screeners
Input: screener_master rows where subcategory IS NULL or classified_by = 'keyword' with low confidence
Step 1: Run expanded keyword ruleset (~120 rules) → assigns category + subcategory + confidence
Step 2: Remaining "other" (confidence < 0.6) → batch call to Ollama with prompt:
"Classify this Indian stock screener: '{name}'. Categories: Momentum|Institutional|Fundamental|Volume|Trend|Reversal|Quality|Growth|Sector|Valuation. Return JSON {category, subcategory, confidence}"
Output: UPDATE screener_master SET subcategory, category_confidence, classified_by
2. screener_performance.py
src/server/screener_performance.py — Python
Nightly after market close
Phase A — Bootstrap from recommendation_log:
Parse signals_json → extract screener_ids active at recommendation time → join outcome → accumulate per-screener win/loss per horizon

Phase B — Fill screener_appearances returns:
SELECT appeared_date, symbol WHERE return_5d IS NULL → join stock_ohlcv → compute return at +5/10/20/60/120 trading days → UPDATE

Phase C — Compute Bayesian score + tier:
For each screener: shrunk_wr = (n×wr + 20×global_mean) / (n+20) → composite → tier A/B/C/D → UPSERT screener_performance_v2

Phase D — Sync tier back:
UPDATE screener_master SET tier = (SELECT tier FROM screener_performance_v2 WHERE scan_id = screener_master.scan_id)
