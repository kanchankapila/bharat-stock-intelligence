Design — Section 1 of 3: Database Schema

2 new tables + additions to 2 existing tables. Does this look right?

NEW TABLE screener_appearances
screener_id TEXT NOT NULL
source TEXT NOT NULL -- 'trendlyne'|'mc'|'et'
symbol TEXT NOT NULL
appeared_date DATE NOT NULL
exited_date DATE -- NULL = still active
return_5d REAL
return_10d REAL
return_20d REAL
return_60d REAL
return_120d REAL
nifty_ret_20d REAL -- benchmark
outcome_20d TEXT -- WIN|LOSS|PENDING
PRIMARY KEY (screener_id, symbol, appeared_date)
Populated on every sync: diff current vs previous snapshot → insert new appearances. Returns filled in by nightly Python job from stock_ohlcv.
NEW TABLE screener_performance_v2
screener_id TEXT PRIMARY KEY
source TEXT NOT NULL
total_appearances INTEGER
resolved_count INTEGER
-- per horizon metrics --
wr_5d / wr_10d / wr_20d / wr_60d / wr_120d REAL
avg_ret_5d / _10d / _20d / _60d / _120d REAL
alpha_20d / alpha_60d REAL -- vs Nifty
sharpe_20d REAL
max_drawdown REAL
bayesian_score REAL -- composite 0–1
tier TEXT -- A|B|C|D|Unranked
data_source TEXT -- 'proxy'|'appearances'|'mixed'
last_computed DATETIME
EXTENDED screener_master
-- existing columns unchanged --
+ subcategory TEXT -- e.g. 'Breakout','MACD Cross'
+ tier TEXT -- A|B|C|D|Unranked
+ category_confidence REAL -- 0–1, how sure is the NLP
+ classified_by TEXT -- 'keyword'|'ollama'|'manual'
tier column synced daily from screener_performance_v2.tier
EXTENDED screener_reliability (existing)
-- existing: win_rate_1d / 7d / 30d kept as-is --
+ win_rate_5d REAL
+ win_rate_10d REAL
+ win_rate_20d REAL -- primary tier input
+ win_rate_60d REAL
+ win_rate_120d REAL
screener_performance_v2 is the canonical source. screener_reliability kept for backward-compat.
