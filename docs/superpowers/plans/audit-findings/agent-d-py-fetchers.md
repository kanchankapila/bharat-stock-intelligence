## Audit Report — Data-Ingestion Layer (`src/server/*_fetcher.py`, `sync_*.py`, `backfill_*.py`, `*_client.py`)

**Scope covered:** 58 files matched the glob patterns, plus `explore_mc_tl.py`, `python_api.py`, `test.py` as requested.

### CRASH findings
None. All 58 target files smoke-imported cleanly, as did `test.py` and `explore_mc_tl.py`. `python_api.py` also imports successfully but takes ~16-22s cold (torch/CUDA init inside `dl_engine.py`, no lazy guard) — noted as MINOR below, not a crash.

### SILENT findings (swallowed exceptions / split-brain-adjacent risk)

- `src/server/mc_advance_decline_fetcher.py:73-79` | SILENT | `_parse_mc_date()` silently relabels any unparseable MoneyControl date as *today* instead of logging/erroring, corrupting `market_breadth.date` attribution with no trace. | Log the raw string and raise, or at minimum `print` a WARN before falling back so bad rows are traceable.
- `src/server/nt_pcr_ts_fetcher.py:63-73` | SILENT | `_get_nt_index_map()` swallows any DB error (missing `index_provider_map` table, connection failure, etc.) and silently substitutes a hardcoded 6-index `_FALLBACK` dict — a real DB/config outage is indistinguishable from normal operation. | Log the exception before falling back; alert if fallback is used more than once in a row.
- `src/server/nt_change_oi_fetcher.py:66-68` and `src/server/nt_oi_snapshot_fetcher.py:76-78` | SILENT | Same fallback-swallow pattern as above, repeated across the `nt_*_fetcher.py` family — systemic, not isolated. | Same fix; consider factoring the index-map lookup into one shared helper in `db_compat.py` with proper logging.
- `src/server/insider_transactions_fetcher.py:265,282` | SILENT | `cutoff = (date.today() - timedelta(days=days)).isoformat()` (a string) is bound to `transaction_date >= ?` against a Postgres DATE column — violates the project's rule #6 date-binding convention (bind `datetime.date`, not strings). | Change to `cutoff = date.today() - timedelta(days=days)` and drop `.isoformat()`.
- `src/server/delivery_volume_fetcher.py:119,134-138` | SILENT | `"date": trade_date.isoformat()` is inserted via `INSERT ... VALUES (?,?,?,?,?,?) ON CONFLICT(symbol, date)`, same rule #6 violation on an upsert key column — risk of the ON CONFLICT match silently misbehaving if implicit string→date cast differs from a bound date object's. | Bind `trade_date` (a `date` object) directly instead of `.isoformat()`.

### MINOR findings

- Systemic pattern | MINOR | 79 occurrences of `.isoformat()` across 40 of the 58 files feed into query params or insert payloads; only a handful (above) were verified as landing on DATE columns via `db_compat`. | Recommend a follow-up systematic pass cross-referencing each `.isoformat()` call site against the actual column type before deciding fix priority.
- `src/server/python_api.py` (outside the strict glob, included per request) | MINOR | Imports `dl_engine`/`torch` unconditionally at module scope, adding ~20s to every cold start/import with no lazy loading. | Defer heavy ML imports into the route handlers if start-up latency becomes a problem.
- Positive finding, no action needed | — | None of the 58 target files import `sqlite3` or `psycopg2` directly — all DB access correctly funnels through `db_compat.py` (`get_engine()`, `connect()`, `query_all()`, `execute()`), including the SQLAlchemy-engine-based fetchers (`fii_dii_fetcher.py`, `pcr_fetcher.py`) which use `db_compat.get_engine()` rather than instantiating their own engine. The AlphaQuant split-brain failure mode does not currently reproduce in this ingestion layer. Also confirmed: the many `except Exception: con.rollback()` blocks (asm_gsm_fetcher.py, block_deal_fetcher.py, index_membership_fetcher.py, mc_*_fetcher.py, trendlyne_*_fetcher.py, working_capital_fetcher.py, etc.) are legitimate idempotent-DDL guards (`ALTER TABLE ADD COLUMN` re-run protection), not fetch-failure swallowing — verified via inline comment in `asm_gsm_fetcher.py:100-125` explaining the Postgres aborted-transaction rationale.
